# Java — Estudos, Exercícios e Desafios

Repositório dedicado ao estudo contínuo de **Java**, reunindo exercícios, desafios, projetos práticos e materiais desenvolvidos durante cursos, Bootcamps e uma trilha autoral de evolução progressiva.

O objetivo é registrar a evolução técnica de forma organizada, mantendo exemplos executáveis, documentação dos problemas resolvidos e histórico de commits que permita acompanhar o avanço dos conceitos básicos até tópicos mais avançados da linguagem e da engenharia de software.

## 🚀 Desafio Java — 30 dias de evolução

A partir de **29 de agosto de 2026**, este repositório passa a receber uma trilha contínua de exercícios Java durante **30 dias**, com dificuldade crescente.

### Rotina

- Período: **29/08/2026 a 27/09/2026**.
- Execuções diárias: **13h, 14h, 15h, 16h, 17h e 18h**.
- Até **6 exercícios por dia**.
- Até **180 exercícios** ao final dos 30 dias.
- Cada execução adiciona um exercício novo.
- A dificuldade não reinicia no início de um novo dia.
- Cada exercício é registrado em um commit próprio e rastreável.

A proposta não é apenas acumular soluções, mas demonstrar uma evolução coerente de raciocínio lógico, domínio da linguagem, orientação a objetos, boas práticas e arquitetura de software.

## 📈 Trilha de aprendizagem

A progressão é adaptativa: cada novo exercício considera o conteúdo já existente e aumenta gradualmente a complexidade.

### Etapa 1 — Fundamentos

- estrutura básica de um programa Java;
- tipos primitivos e variáveis;
- entrada e saída de dados;
- operadores aritméticos, relacionais e lógicos;
- estruturas condicionais;
- estruturas de repetição.

### Etapa 2 — Resolução de problemas

- arrays e matrizes;
- manipulação de `String`;
- métodos;
- parâmetros e retornos;
- decomposição de problemas;
- algoritmos de busca e ordenação introdutórios.

### Etapa 3 — Orientação a Objetos

- classes e objetos;
- construtores;
- encapsulamento;
- composição;
- herança;
- polimorfismo;
- classes abstratas;
- interfaces.

### Etapa 4 — Java intermediário

- Collections Framework;
- `List`, `Set` e `Map`;
- Generics;
- expressões Lambda;
- Stream API;
- tratamento de exceções;
- leitura e escrita de arquivos.

### Etapa 5 — Qualidade e engenharia de software

- separação de responsabilidades;
- código limpo;
- princípios SOLID;
- testes automatizados;
- refatoração;
- modelagem de domínio;
- padrões de projeto aplicáveis aos exercícios.

### Etapa 6 — Desafios integradores

- estruturas de dados;
- concorrência e Threads;
- processamento de dados;
- problemas com múltiplas classes e camadas;
- pequenos sistemas Java;
- aplicação conjunta de POO, Collections, Streams, exceções e testes;
- decisões introdutórias de arquitetura de software.

## 📂 Organização dos exercícios progressivos

Os novos desafios são organizados dentro de:

```text
Exercicios-Progressivos/
├── 001-nome-do-exercicio/
│   ├── README.md
│   └── src/
│       └── Main.java
├── 002-nome-do-exercicio/
│   ├── README.md
│   └── src/
│       └── Main.java
└── ...
```

Quando a complexidade exigir, um exercício poderá possuir múltiplas classes, pacotes e testes.

Cada diretório deve ser autocontido e possuir documentação suficiente para que o problema possa ser compreendido independentemente da solução.

## 📝 Padrão de documentação dos exercícios

Cada exercício da trilha deve apresentar, sempre que aplicável:

1. **Enunciado** — descrição objetiva do problema.
2. **Requisitos** — regras que a implementação deve atender.
3. **Entrada e saída esperadas** — exemplos de utilização.
4. **Conceitos praticados** — recursos da linguagem trabalhados.
5. **Abordagem da solução** — explicação resumida do raciocínio utilizado.
6. **Implementação** — código Java completo e executável.
7. **Validação** — casos de teste ou cenários utilizados para conferir a solução.

## 🧭 Princípios da trilha

Os exercícios seguem algumas regras para manter uma evolução técnica consistente:

- não repetir problemas já existentes;
- aumentar a dificuldade gradualmente;
- privilegiar soluções legíveis antes de otimizações prematuras;
- utilizar nomes claros para classes, métodos e variáveis;
- evitar responsabilidades excessivas em uma única classe;
- introduzir abstrações somente quando agregarem valor ao problema;
- aplicar boas práticas compatíveis com o nível de cada exercício;
- registrar decisões importantes na documentação do próprio desafio.

## 🔀 Padrão de commits

A trilha utiliza **Conventional Commits** para deixar o histórico do GitHub legível e facilitar o acompanhamento da evolução.

Exemplos:

```text
feat(exercises): add level 01 conditional challenge
feat(exercises): add array statistics challenge
feat(exercises): add object-oriented banking challenge
refactor(exercises): improve domain responsibilities
test(exercises): add validation scenarios
docs: update progressive exercise roadmap
```

Como regra, cada novo exercício deve ser entregue em um **commit atômico**, contendo apenas os arquivos necessários para aquele desafio.

## ▶️ Executando os exercícios

Para utilizar o repositório localmente:

```bash
git clone https://github.com/LindembergueFrank/Java.git
cd Java
```

Entre no diretório do exercício desejado e siga as instruções apresentadas em seu respectivo `README.md`.

Para exemplos simples contendo apenas `Main.java`:

```bash
javac Main.java
java Main
```

Exercícios que utilizarem Maven, Gradle, testes ou outra estrutura terão os comandos específicos documentados em seu próprio diretório.
